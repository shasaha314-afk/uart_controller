# UART Transceiver in Verilog (FPGA)A full-duplex UART (Universal Asynchronous Receiver/Transmitter) written in synthesisable Verilog. It runs at 115,200 baud from a 50 MHz clock, with separate transmitter and receiver FSMs and a 16x-oversampled receiver. It is verified with a loopback testbench over all 256 byte values, then synthesised and implemented in Vivado for a Zynq-7000 (`xc7z010clg400-1`).> **Scope:** verified in simulation and taken through synthesis and implementation. It has **not** been tested on a physical board (no I/O pin constraints are included).## Results| Metric | Result ||---|---|| Baud rate / clock | 115,200 bps / 50 MHz || Loopback test | **256 / 256 PASS** (0x00 to 0xFF), 100% data integrity || LUTs | 49 (0.28%) || Flip-flops | 56 (0.16%) || I/O / BUFG | 33 (33%, top-level ports) / 1 || Setup WNS | +15.471 ns at a 20 ns (50 MHz) constraint, 0 failing endpoints || Hold WHS | +0.154 ns || Est. Fmax | ~220 MHz (computed as 1 / (20 - 15.471) ns, a slack-based estimate) || Total on-chip power | 0.093 W (0.091 W static, 0.002 W dynamic; Vivado confidence: low) |Tool: Xilinx Vivado ([version]), default synthesis and implementation strategies.## Architecture| Module | File | Description ||---|---|---|| Top level | `uart.v` | Instantiates and connects the baud generator, TX and RX || Baud generator | `baudrate.v` | Two accumulators: TX enable every 434 clocks, RX enable every 27 clocks (16x oversampling) || Transmitter | `transmitter.v` | 4-state FSM `IDLE -> START -> DATA -> STOP`, LSB first, `Tx_busy` flag || Receiver | `receiver.v` | 4-state FSM with 16x oversampling, start-bit validation at mid-bit, data sampled at bit centre, stop-bit check |

**Transmitter:** on `Tx_en` it latches the data byte, then each state advance is gated by the baud enable `Txclk_en`.**Receiver:** detects the falling edge, waits 8 ticks to the middle of the start bit and confirms it is still low (rejecting glitches). It then samples each data bit every 16 ticks and checks the stop bit before latching `data` and asserting `ready`. The consumer clears it with `ready_clr`.### Baud generation| Parameter | Value ||---|---|| `TX_ACC_MAX` | 50,000,000 / 115,200 = 434 cycles per bit || `RX_ACC_MAX` | 50,000,000 / (115,200 x 16) = 27 cycles per oversample tick |Integer division means the TX bit is 434 cycles (about +0.006% baud error) and the RX bit is 16 x 27 = 432 cycles (about +0.5%). The resulting mismatch is small compared with the receiver's mid-bit sampling margin, and the loopback test passes on every byte.## Repository structure```.├── rtl/│ ├── uart.v│ ├── baudrate.v│ ├── transmitter.v│ └── receiver.v├── tb/│ └── uart_tb.v├── constraints/│ └── uart_constraints.xdc├── docs/│ ├── UART_Report.pdf│ └── (waveform, utilization, timing and power screenshots)└── README.md```

## Simulation`uart_tb.v` connects `Tx` directly to `Rx` (loopback) with a 50 MHz clock. For each value `0x00`-`0xFF` it starts a transmission, waits for `Tx_busy` to rise and fall, waits for `ready`, compares received and sent data, and prints PASS/FAIL. It ends with a summary:```TOTAL: 256 PASS, 0 FAIL out of 256 bytesData integrity: 100%```1. Create a Vivado project for part `xc7z010clg400-1`.2. Add `rtl/*.v` as design sources, `tb/uart_tb.v` as a simulation source, and `constraints/uart_constraints.xdc` as constraints.3. Set `uart_tb` as the simulation top and run Behavioural Simulation (a `uart.vcd` waveform is also dumped).4. Run Synthesis and Implementation, then open the utilization, timing and power reports.The only constraint is the clock: `create_clock -period 20.000 -name clk_50m [get_ports clk_50m]`.## Debugging noteAn early receiver version returned directly to the START state after a byte instead of a dedicated IDLE state. The sample counter was therefore non-zero when the next start bit was searched for, which desynchronised reception. Adding an explicit IDLE state that resets all counters before watching for the next falling edge fixed it, and the 256-byte loopback test confirms the fix.## Limitations and future work- Add a 2-flip-flop synchroniser on `Rx` for use with a real asynchronous line- Framing-error flag, optional parity, and configurable data or stop bits- TX/RX FIFOs and a runtime-configurable baud rate- Pin constraints and an on-board test## Author**Shashwat Saha** - B.Tech Electrical Engineering, IIT Mandi[LinkedIn](https://linkedin.com/in/shashwat-saha-085310285) | shasaha314@gmail.com
